## 0. 一句话总结

把框架里用 `#if ENABLE_*` 条件编译塞进主包的可选功能（授权管理、备份接收端），重构成**独立 NuGet 插件包 `SB.Feature.*`**，实现"引包即启用 + `Features:Disabled` 黑名单可关 + 启动日志打清单"。PM 作为第一个落地项目，已接入两个插件并把自身业务也 feature 化。

**唯一未完成**：PM 部署到测试环境（容器 192.168.10.73，PG 库 `sbpm`）连真库实跑，验证菜单/建表/签发功能。本地连不上该 PG，故只验证到编译 + 发现层。

## 2. 用户拍板的关键决策（不要推翻）

1. **自动发现 + 默认启用 + 配置可关**：deps.json 扫 `SB.Feature.*`，自动装配，`appsettings` 的 `"Features":{"Disabled":["X"]}` 黑名单可关某个，启动日志打 `[Features] loaded: ...`
2. **主权功能（授权验证）独立于插件体系**：继续 `#if DISABLE_LICENSE` 双变体，两套机制并存，**不**做成插件
3. **派生项目无包袱**：纯从架构最优出发，PM/Nexus 可为适配重新调整
4. **开发期框架内部用 ProjectReference，发包时 dotnet pack 自动转包依赖**（变体由发包参数收敛，不写死 NoLicense）
5. **BaseCrudService 下沉 Core**：49 个继承点直接改 using，不留转发壳
6. **PM 业务也 feature 化**：废除 Program.cs 手动 AddPmServices，统一 IFeatureModule 范式
7. **包名 `SB.Feature.*`**（不是 `SB.Framework.Feature.*`）

## 3. 框架侧改动（已全部完成并发包）

### 3.1 新增插件基础设施（`SB.Framework.Core/Features/`）
| 文件 | 职责 |
|---|---|
| `IFeatureModule.cs` | 插件清单接口（FeatureName/DisplayName/FeatureAssemblies/EnabledByDefault/OptionsType/ConfigureServices/Configure） |
| `FeatureContext.cs` | 装配上下文 |
| `DependsOnFeatureAttribute.cs` | 插件依赖声明（拓扑排序用） |
| `FeatureScanner.cs` | 读 `DependencyContext.Default.RuntimeLibraries`（.deps.json）发现 `SB.Feature.*`，用 `GetDefaultAssemblyNames` 取真实程序集名（不用包名，避开 .NoLicense 后缀坑） |
| `FeatureCatalog.cs` | 单一真相源 `FeatureRuntime.Catalog` + 黑名单过滤（程序集清单层，一处过滤三处生效）+ `LogStartupSummary` |
| `FeatureModuleActivator.cs` | 实例化清单 + 应用 EnabledByDefault + Kahn 拓扑排序 + 缓存供 Add/Use 两阶段复用。**扫描范围 = enabled feature 程序集 + 项目程序集（catalog.ProjectAssembly）** |
| `IFeatureSingleFilePublish.cs` | 单文件发布兜底接口（当前未用，deps.json 路径够用） |

### 3.2 三套发现机制接入 catalog（核心改造）
全部从"写死 `Assembly.Load("SB.Framework.Services")` + 单 ProjectAssemblyName"改为"遍历 `catalog.AllScanAssemblies`"：
- `ServiceSetup.AddBusinessServices(FeatureCatalog)` — `[AutoDependencyInjection]` 扫描（保留旧字符串重载作兼容缝）
- `SetupService.DiscoverModuleInitializers(FeatureCatalog)` — IModuleInitializer 发现（保留旧重载）
- `SbFrameworkExtensions` 里 `AddControllersWithViews` 后 `mvc.AddApplicationPart(asm)` — 跨程序集 Controller 发现（框架硬编码，[F-4]）

### 3.3 装配点（`SbFrameworkExtensions.cs` 七个 F-1~F-7）
- AddSbFramework：[F-1]发现 → [F-2]AddBusinessServices(catalog) → [F-3]feature ConfigureServices+Options绑定 → [F-4]AddApplicationPart

**部署后验证清单**：
1. **启动日志**应出现：`[Features] loaded: BackupReceive, LicenseManage, PmCore`

2. **后台菜单**应新增：

3. **数据库建表**：`backup_remote_record` 表由 BackupReceive 插件建；4 张 License 表（SB_License_*）由核心 AdminService 建
4. **接口可达**：`/api/BackupReceive/Upload`、`/Entitlement/*`、`/api/verify/*`

### 6.2 如果出问题排查方向
- **feature 没被发现**（日志无 `[Features] loaded` 或缺某个）→ 查产物 deps.json 是否列出该程序集；查 appsettings ProjectAssemblyName 是否正确
- **菜单没出来** → 查 IModuleInitializer 是否被扫到（DiscoverModuleInitializers 走 catalog）；查 SeedDatabase 日志
- **Controller 404** → 查 AddApplicationPart 是否对该 feature 程序集执行（[F-4]）
- **启动 500/崩溃** → appsettings 加 `"ExposeErrorDetails": true` 看详细错误；常见是 IFreeSql 未注册（installed.lock 缺失）
