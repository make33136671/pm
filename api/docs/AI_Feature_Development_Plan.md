## 1. 当前状态

### 已完成的 AI 基础设施

- **IAiProvider** — 底层 AI 模型调用接口，支持 SendAsync
- **IAiProviderAdapter** — 模型适配器接口（注入式，按 ProviderType 匹配）
- **ActiveAiProvider** — 从数据库读取 Active 配置，自动选择适配器
- **AiProviderFactory** — DI 自动收集所有 IAiProviderAdapter 实现
- **DefaultAiService** — 业务编排层（AnalyzeCode / GenerateCode / DesignFeature / ReviewCode / Chat）
- **AiController** — REST API（POST /Ai/Chat、/Ai/Execute 等）
- **LlamaAiProviderAdapter** — 新增，连接内网 llama.cpp（192.168.10.80:8080）
- **AiProvider 种子数据** — Stub / Hermes / Llama 三种预设
- **Admin 前端页面** — `/system/ai-provider` 列表/编辑，按适配器自动生成下拉选项
- **AI 聊天页面** — `/ai/chat` 支持自由对话和四种任务类型

### 待部署

- 构建 api.zip → 通过 PM Admin 上传部署 → 在 AI 提供商页面启用 Llama.cpp

## 2. 功能路线图

### Phase 1: AI 按钮型功能（MVP）

#### 功能 A：需求一键任务分解

| 条目 | 内容 |
|------|------|
| **触发入口** | 需求详情页面（Requirement）→ "AI 分解任务" 按钮 |
| **数据流** | 前端点按钮 → 调 Agent API 或 Admin API → DefaultAiService.Chat() → llama.cpp |
| **AI 输入** | 需求标题+描述+项目上下文 |
| **AI 输出** | 结构化任务列表（任务名、负责人建议、优先级、预估工时） |
| **后端落地** | 解析 AI 输出 → 批量创建 TaskItem 记录 → 返回结果 |
| **用户感知** | 按钮 → loading → 弹出确认框显示 AI 生成的任务列表 → 一键确认创建 |
| **难度** | ⭐⭐（前端加按钮 + 后端加 Service 方法） |
| **优先级** | P0 |

#### 功能 B：需求/任务智能补充

| 条目 | 内容 |
|------|------|
| **触发入口** | 需求/任务编辑页 → "AI 补充内容" 按钮 |
| **数据流** | 前端点按钮 → 调 AiController.Chat() |
| **AI 输入** | 需求标题 + 已有内容 |
| **AI 输出** | 补充建议：验收标准、技术方案、相关注意事项 |
| **后端落地** | AI 返回 Markdown 文本 → 前端以建议弹窗显示，用户可一键填入编辑框 |
| **难度** | ⭐（纯前端 + 已有 Chat API） |
| **优先级** | P1 |

#### 功能 C：变更日志自动生成

| 条目 | 内容 |
|------|------|
| **触发入口** | 项目发布/版本管理页 → "AI 生成变更日志" 按钮 |
| **数据流** | 前端点按钮 → 调 AiController.Chat()，传近期待办任务列表 |
| **AI 输入** | 项目名称 + 时间段内已完成的任务列表 |
| **AI 输出** | Changelog (按类型分类：新功能/修复/优化等) |
| **后端落地** | AI 返回 Markdown → 用户可直接复制到发布描述或提交到文档模块 |
| **难度** | ⭐（纯前端 + 已有 Chat API + 读取任务列表） |
| **优先级** | P2 |

---

### Phase 2: AI + 代码能力

#### 功能 D：代码质量分析

| 条目 | 内容 |
|------|------|
| **触发入口** | 项目详情页或 CI/CD 页 → "AI 代码分析" 按钮 |
| **数据流** | 前端点按钮 → 后端读项目关联的 Git 仓库代码 → 发 AI 分析 |
| **AI 输入** | 项目代码片段 + 关注的文件路径 |
| **AI 输出** | 分析报告（Bug/性能/安全/架构问题） |
| **后端落地** | 需要 PM 服务器能访问代码仓库（SSH 或本地克隆），或通过 WebTerminal 读取 |
| **前提** | 项目配置中记录 Git 仓库地址和访问凭证 |
| **难度** | ⭐⭐⭐（需要打通 PM 服务器到 Git 仓库的网络和权限） |
| **优先级** | P3 |

#### 功能 E：智能搜索

| 条目 | 内容 |
|------|------|
| **触发入口** | 全局搜索框或项目内搜索 → "AI 搜索" 按钮 |
| **数据流** | 输入自然语言 → 后端 AI 解析意图 → 在 PM 数据库执行适配查询 |
| **AI 输入** | 用户自然语言描述（如 "上个月未完成的需求"） |
| **AI 输出** | 理解后的搜索条件 + 匹配的结果列表 |
| **后端落地** | AI 将自然语言转为结构化查询参数 → 调现有查询接口 → 返回结果 |
| **难度** | ⭐⭐⭐（需要设计查询意图映射，效果依赖模型能力） |
| **优先级** | P3 |

## 4. 关键决策点

1. **AI 分解任务的输出解析方式** — AI 返回 JSON 结构？还是要加 ````split` 标记让后端正则解析？
2. **任务分解的确认机制** — 一键创建（不确认）vs 弹出确认框让用户编辑后再提交？
3. **代码分析的前提** — 项目代码在 PM 服务器本地有？还是需要通过 SSH 连 GitLab？
4. **智能搜索的精度要求** — 允许模糊匹配 + 人工筛选，还是必须精确转换？

## 5. AI 对 PM 系统的能力边界

| 能力 | 当前状态 |
|------|----------|
| 读项目/需求/任务/CI/CD 数据 | ✅ 通过 Agent API 可读 |
| 写需求/任务/CI/CD 记录 | ✅ 通过 Agent/Admin API 可写 |
| 读取项目代码（本地） | ⚠️ 需要 PM 服务器能访问代码目录 |
| 执行代码变更 | ❌ 需要打通 Git 操作链路 |
| 触发 CI/CD pipeline | ✅ Agent API 已有 |
| 读取 Git 仓库 commit/diff | ⚠️ 需配置 Git 访问凭证 |
| 管理用户/权限/Token | ❌ 防提权限制，不可达 |
